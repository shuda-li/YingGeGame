# 《踏鼓 / Project Drumbeat》游戏策划案

**副标题**：英歌舞主题横版动作闯关游戏 · 含「如何靠 AI 一步步做完全」的开发路线图

- 项目：踏鼓 / Project Drumbeat
- 归属：潮汕英歌舞非遗数字化传承与创新实践 · 第 8 小组游戏开发组
- 版本：v1.0　｜　日期：2026-10-13
- 关联文档：详细设计文档、合拍判定与节拍表、ADR-001 决策记录、M0 原型任务清单、M0 开发状态、豆包像素提示词套件

> 本策划案以「已有 M0 可玩原型 + 新到位的像素素材包」为起点，重点回答一件事：**接下来用 AI 如何一步一步把游戏做完。**

---

## 一、项目定位

- **类型**：2D 横版动作闯关（跑酷 + 节奏判定 + 对击弹反）
- **核心幻想**：玩家扮演英歌队的槌手，踩着锣鼓鼓点一路巡游、挥槌破阵，把「英歌舞的节奏感」变成可以上手的操作快感
- **一句话**：一款「跟着鼓点打」的英歌舞横版闯关游戏——鼓点就是节拍器，合拍就是伤害倍率
- **目标平台**：PC（键鼠 / 手柄）；浏览器 Web（课程成果展示用）
- **时长**：单关 3–5 分钟，全流程 12–15 分钟
- **目标玩家**：校内师生与成果展示观众；对非遗题材感兴趣的轻度玩家；想了解英歌舞的年轻人

**设计支柱**

1. 鼓点驱动：音频时钟是唯一时间基准，帧率波动不影响判定结果
2. 合拍即爽点：踩准判定点出招有明确倍率与反馈
3. 跑打无缝：跑酷态与战斗态共享同一套位移参数，切换不重置速度
4. 文化不失真：动作、鼓点、场景均能在潮汕英歌中找到依据

## 二、美术风格规范

**风格**：像素风（16-bit 取向），角色为清晰像素块 + 硬边描边，背景为像素化中式建筑群 + 视差层。

**素材来源**：`art-source/picture/` 图片包，由豆包 Seedream 生成，提示词见《豆包像素素材提示词套件》。

**抠图规则**
- 底色为品红 `#FF00FF`（部分经 JPEG 压缩后偏玫红 `#E00060`）
- 必须用**边界泛洪填充**（只删与画面边缘连通的底色），再按「B 通道远大于 G 通道」清除被角色包围的残余
- **背景层不做粉色清除**（粉霞、粉墙是画作本身）；角色红色戏服不会被上述规则误伤

**渲染尺度**
- 建议 `PIXELS_PER_UNIT = 80`，屏幕 1280×720，可见世界 16×9 单位
- 角色屏幕高度约 **149px**（原画内容高 894px/跑动、1494px/敌人站姿，统一整数倍下采样：玩家 1/6、敌人 1/10）

**调色板**（锁定 24–32 色）
- 英歌红 `#D11430`、粉白 `#FBEFF3`（脸谱/裤）、金 `#D4A017`（描边/头饰）、夜蓝 `#12203A`（敌人劲装）、青绿 `#2E7D6B`（腰饰/建筑彩绘）

**版式规则**
- 只做朝右，程序按 `facing` 水平翻转
- 角色以脚底中心为原点对齐地面
- 统一 PNG-32 透明底
- 命名：`characters/player/<state>.png`、`characters/enemy/<state>.png`、`environment/<层名>.png`、`ui/<名称>.png`

**视差层**
- 天空：`environment/天空.png`
- 云层：`云朵_2` / `云朵_3`（缓慢横移）
- 远景：`远景层_1`（山峦 + 村落）/ `_2` / `_3` / `_4`
- 前景：`前景层_1–4`（灯笼等，用于近景遮挡与纵深）
- 地面：`ground_tile.png`（石砖，需人工做无缝平铺）
- 底图：`level_map.png`（祠堂建筑全景）

## 三、核心玩法系统

**核心循环**：巡（跑酷推进）→ 击（合拍挥槌）→ 蓄鼓（鼓劲槽）→ 满堂彩（爆发）→ 收阵（结算）

| 编号 | 系统 | 规则要点 | 数据表 |
| --- | --- | --- | --- |
| S1 | 合拍判定 | 按键帧锚点；完美 ±40ms、合拍 ±80ms；音频时钟驱动；反馈在按键帧立即触发；伤害只在实际命中时结算 | `feel_params.json` / `beat_tables.json` |
| S2 | 锣鼓节奏与板式 | 慢板 90 / 中板 110 / 快板 140 / 极板 150（待确认）；分层离散切换，仅小节边界换板，层内 ±8% 微调；判定点固定在第 1、3 拍 | `tempo_layers.json` / `beat_tables.json` |
| S3 | 运动与手感 | 固定步长 1/120s；疾行、腾跃、二段跳、抢步、矮子步；起跳缓冲、土狼时间、取消窗口可实时调 | `feel_params.json` → motion/assist |
| S4 | 帧数据战斗 | 挥槌三段、凌空挥槌两段、劈山、对击；startup-active-recovery 驱动；取消窗口在 recovery 后 40% | `frame_data.json` |
| S5 | 对击弹反 | 敌人命中前 100ms 内按攻击触发；成功硬直 1.2s 且 +25 鼓劲；落在判定点为「合拍弹反」鼓劲 ×2；过早按键进入 12 帧破绽 | `feel_params.json` → combat |
| S6 | 鼓劲槽与满堂彩 | 疾行增速 + 槌花命中 + 合拍倍率 + 弹反加成；停止进攻 3s 后衰减；满槽且连段 ≥4 释放 | `feel_params.json` → drum_energy |

**操作**

| 操作 | 按键 |
| --- | --- |
| 移动 | A / D |
| 跳跃（二段跳） | 空格 |
| 攻击（合拍锚点） | J |
| 抢步 | L 或 Shift |
| 矮子步 | S |
| 满堂彩 | F |
| 调试 | F1 判定面板 / F2 手感面板 / R 重开 / P 暂停 / ESC 退出 |

## 四、关卡结构

共 3 关，难度递进：

- **L1「英歌初醒」**：慢板 90；教学移动 + 击槌 + 合拍判定；敌人巡逻兵 ×2；美术复用祠堂廊柱（`level_map` 中段 + `远景层_1`）。**M0 原型已实现该赛段骨架。**
- **L2「双龙出海」**：中板 110 → 快板 140（小节边界换板）；教学跳跃 / 二段跳 + 对击弹反 + 抢步；敌人巡逻兵 ×4 + 远程鼓师 ×1；美术骑楼街景（前景灯笼做纵深遮挡）。
- **L3「战舞传承」**：快板 140 → 极板 150（高潮段）；综合运用 + 满堂彩终结；敌人关底 Boss（英歌领队）+ 杂兵；美术祠堂正殿 + 全景背景 + 锣鼓阵。

**关卡数据格式**：每关一个 JSON（`world` / `solids` / `hazards` / `low_walls` / `enemies`），沿用 `level_segment.json` 的结构。

## 六、技术方案

- **运行时**：Python 3.10+ + pygame 2.x + numpy + sounddevice
- **为什么**：零基础团队可上手；音频时钟与固定步长运动可直接控制；跨平台；可打包 exe 或发布 Web
- **AI 工具**：Trae（AI 集成开发环境）+ DeepSeek 模型辅助编程
- **打包**：PyInstaller（`--onefile --windowed`）产出可直接双击运行的 exe；Web 版可用 pygbag 或 Trae 发布能力
- **数据驱动原则**：所有数值走 JSON 数据表，改数值不改代码；让 AI 改玩法时优先改数据表，减少回归风险

**工程结构（要点）**

```
drumbeat-m0/run.py            开发运行入口
drumbeat-m0/drumbeat/app.py   主循环与运行时装配
drumbeat-m0/drumbeat/         12 个模块（运动/战斗/判定/节奏/音频/渲染/输入…）
drumbeat-m0/drumbeat/data/    五张数据表
drumbeat-m0/assets/           像素素材（角色/敌人/环境/UI）
drumbeat-m0/tools/smoke_test.py  无窗口冒烟测试
```

## 七、如何靠 AI 一步步做完全（核心章节）

### 7.1 工作方法

**小循环**：描述需求 → 让 AI 改代码/数据 → 本地实跑 → 记录问题 → 让 AI 修 → 再运行。

**四条纪律**

1. 每次只提一个明确目标（如「给第 2 关加一个远程鼓师」），不要一次提一堆
2. 让 AI 优先改 `drumbeat/data/*.json`，代码改动尽量小
3. 涉及美术时先给素材文件名与规格，再让 AI 写贴图加载层
4. 每次改动后必须实跑一次并记录，避免「看起来改好了其实没跑通」
5. 版本用 Git 管理，每完成一个里程碑打一次 tag，方便回退

### 7.2 M0 可玩原型（已完成）

- **目标**：单赛段可通关，合拍判定跑在音频时钟上
- **产出**：`drumbeat-m0` 原型 + 冒烟测试 PASS（通关、敌人 2/2、完美率 86%、Δt 均值 -3.4ms）

### 7.3 M1 素材接入与风格统一

**目标**：把像素素材替换掉现有色块占位，画面统一为像素风。

- **M1-1 素材落位**（已完成）
  - 做法：`art-source/picture/` → `drumbeat-m0/assets/`（抠图、分帧、统一整数倍缩放），清单见 `assets/manifest.json`
  - 验收：预览图中角色完整、无品红残留、比例一致
- **M1-2 写贴图加载层**
  - 做法：让 AI 在 `hud.py` 加「贴图加载 + 缺图回退色块」：按 assets 命名自动加载，缺图回退程序绘制
  - 给 AI 的指令要点：新增 assets 加载模块；按 state 名查表；支持水平翻转；脚底中心对齐；加载失败静默回退，不许崩
  - 验收：把 assets 临时改名 → 游戏仍能跑（回退生效）；恢复后角色显示为像素图
- **M1-3 统一渲染尺度**
  - 做法：让 AI 把 `PIXELS_PER_UNIT` 从 40 调到 80，同步调整相机与关卡坐标尺度，使角色约 149px 高
  - 给 AI 的指令要点：只改常量与相机换算；关卡 JSON 坐标按 2 倍同步缩放；保证原关卡仍可通关
  - 验收：冒烟测试仍 PASS；角色与障碍比例自然，跳跃高度不遮挡视线
- **M1-4 接入视差背景**
  - 做法：用 environment 层替换纯色远景：天空 + 云朵缓慢横移 + 远景层 + 前景灯笼遮挡
  - 验收：三层视差随相机移动、无明显接缝；帧率不低于 55

### 7.4 M2 玩法补全与三关落地

**目标**：把动作、敌人、三关做齐，玩法闭环完整。

- **M2-1 玩家动作补全**
  - 做法：补齐 idle / dash / slide / hurt 与挥槌三段、凌空挥槌、劈山、对击的动画帧；帧数对齐 `frame_data.json`（**active 帧必须落在视觉最亮帧**）
  - 给 AI 的指令要点：先让 AI 写「帧数据驱动动画播放器」（按 startup/active/recovery 切帧），再补素材逐帧接入
  - 验收：招式动画与判定提示同步无错位；取消窗口手感与设定一致
- **M2-2 敌人扩展**
  - 做法：新增远程鼓师（投掷鼓槌）与 Boss（英歌领队：多段攻击 + 对击窗口）
  - 验收：新敌人前摇清晰可读；对击窗口能稳定触发弹反
- **M2-3 三关关卡**
  - 做法：按 `level_segment.json` 结构，让 AI 生成 L2/L3 的 JSON；代入各自 tempo 与敌人配置
  - 给 AI 的指令要点：给出关卡设计要点（主题、节奏、教学目标、敌人数量），让 AI 输出 JSON；人工在调试面板实跑微调坐标
  - 验收：三关均可通关；每关 3–5 分钟；难度递增合理
- **M2-4 HUD 与结算**
  - 做法：用 ui 素材接入胜负结算界面；补齐判定圈、4 拍鼓面、鼓劲槽的像素美化
  - 验收：通关/落败界面显示正确，与游戏内 HUD 风格一致

### 7.5 M3 音频、打磨与发布

**目标**：声音与表现到位，产出可展示的成品并发布。

- **M3-1 音频**：优先沿用 `synth.py` 程序化锣鼓；有条件替换为真人锣鼓循环（四档板式）与反馈音。验收：四档切换在小节边界无缝；判定点音色清晰可辨
- **M3-2 手感与难度打磨**：用 F2 面板做真人试玩调参；按 OQ-1 规则决定是否收紧/放宽判定窗口。验收：试玩者完美率 55%–75%，未合拍率 <15%
- **M3-3 打包与发布**：让 AI 固化打包脚本（`PyInstaller --onefile --windowed`，显式 collect 音频依赖）；Web 版用 pygbag 或 Trae 发布能力。验收：exe 双击可运行、有声音、无 `crash.log`；Web 版可被浏览器打开
- **M3-4 展示物料**：录演示视频、写项目说明、准备成果展示流程。验收：第 7 次课可直接演示

## 九、风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 生成动作帧不一致（角色长相漂移） | 先用提示词 B 出定妆图，之后每个状态都以「定妆图 + 妆造照片」为参考 |
| 素材帧数与 `frame_data.json` 不匹配导致判定提示错位 | 以数据表帧数为准手工补帧；active 帧必须落在视觉最亮帧 |
| 改渲染尺度后关卡手感变化、原关卡不可通 | 改完立即跑 `tools/smoke_test.py`，要求仍 PASS |
| 范围失控（想做太多关/太多系统） | 严格按月里程碑推进，M2 只做 3 关，不做成长系统与联网 |
| 版权与肖像风险 | AI 素材自生成；真人演出照片仅作参考不出镜；音频优先自录或免费版权 |
