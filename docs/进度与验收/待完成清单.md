## 一、指挥 AI 的六条铁律（先读这段，比读任务更重要）

1. **一次只让 AI 做一件事。** 不要说「把游戏完善一下」，要说「给玩家加 idle 待机动画」。任务越具体，AI 越不会跑偏。
2. **优先改数据表，其次改代码。** 数值、节奏、关卡、动作帧都在 `M0/drumbeat/data/*.json` 里。要调手感、改难度、加关卡，**先让 AI 改 JSON**，不要让它改逻辑代码。
3. **AI 说「改好了」不等于真改好。** 你必须**实跑一遍**。最小验证就是那两条命令（见第七节）。跑过才算完成。
4. **报错要连日志一起丢给 AI。** 只说「报错了」它会瞎猜；把完整的 `Traceback` 和复现步骤一起给，它能一次修对。
5. **不许 AI 改判定核心。** `judgement.py` 与 ADR-001 的四条约定（按键帧锚点、极板 150、分层离散换板、判定点在第 1/3 拍）是已经拍定的设计，除非全组一致同意，否则任何改动都要在提示词里明确写上「不得改动」。
6. **每个任务做完先提交再开下一个。** `git add` 具体文件 → 提交（写清做了什么）→ 推送。出问题时 `git log` 能救你。

## 二、标准指令模板（五段式，复制填空即可）

```
【背景】我是《踏鼓》项目开发组，Python + pygame 横版动作游戏，工程在 drumbeat-m0/。
【目标】<一句话说清要达成什么效果>
【约束】不要改 <列出不能动的文件/模块>；<其他限制，如"缺素材时要能回退"、"不要引入新依赖">
【改动】<列出具体文件与做法，越具体越好>
【验收】改完后运行 <验证命令>，并把输出结果贴给我确认；如果失败请自己修到通过。
```

**示例（可直接用）**：

```
【背景】《踏鼓》是 Python + pygame 的横版动作游戏，工程在 drumbeat-m0/。

【验收】运行 python tools/smoke_test.py 必须打印 SMOKE: PASS；再运行 python tools/preview.py preview_out 14 出图确认。
```

### 出图规格与提示词

中文名与英文名都行，但**文件名必须与代码里的键一致**（在 `assets.py` 里维护映射表）。
出图提示词直接使用：[豆包像素素材提示词套件](../策划案/project-drumbeat-doubao-pixel-prompt-kit.md)。

**⚠️ 出图铁律**：先出一张「角色定妆参考图」，之后**每个状态都以定妆图 + 妆造照片两张参考图**生成，只改「动作」那一段——否则同一个角色每张长相都不一样。

## 十、遇到问题怎么办

| 情况 | 做法 |
|---|---|
| AI 改完跑不通 | 把**完整 Traceback + 复现步骤**贴给 AI，让它自己修到 `smoke_test` PASS |
| AI 改跑偏了（动了不该动的地方） | 直接说「回退这次改动」，用 `git checkout -- <文件>` 恢复，再用更具体的提示词重来 |
| 不确定该不该改某个设计 | 先查 `docs/设计文档/project-drumbeat-decision-ADR-001.json`，涉及四条约定的必须全组同意 |
| 画面出现色块 | 说明该状态素材缺失 → 查第四节缺口表补素材，不要改代码 |
| 判定手感不对 | 先开 F2 面板调，再开 F1 看 Δt；数值定下来后让 AI 写回 `feel_params.json` |
| 想加新功能 | 先问"能不能只改 JSON 数据表实现"，能就不要改代码 |
